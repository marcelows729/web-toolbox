### 計算仕様

- 固定回数・チェックは完了数。日次/週次境界で0へ戻る。週次は設定曜日。日本時間をUTC+9として計算し、利用端末のタイムゾーンには依存しない。
- 蓄積型は保有残数。日次境界を跨いだ回数×補充分を加算し、上限で止める。週次で消去しない。
- オードエネルギーは入力時の基準から3時間ごとに15を加算する候補モデル。変更時も3時間未満の端数時間を維持する。560/840で止める。全キャラ共通の固定時刻回復や満タン時の回復位相停止は未確認であり、モデルに仮定しない。
- 未入力の蓄積・資源は「未入力」と表示し、自動回復しない。0を入力すると明示的に基準時刻を確立する。±操作も入力となる。
- 自動計算無効なら値を維持する。有効化/時刻/曜日の変更は既存値を維持して基準時刻・期間を再設定し、過去分を新設定で遡及加算しない。上限変更時は旧上限で経過分を計算し、新上限を適用する。
- 逆行した端末時計で負の補充をしない。時計の正確性は端末に依存する。表示は30秒間隔/フォーカス復帰時に再計算し、操作は操作時の現在時刻で処理する。
- 保存識別子はJSON配列で区切り衝突を防止。キャラ枠はアカウント+サーバー+キャラ、サーバー枠はアカウント+サーバー、アカウント枠はアカウント。同一アカウントの別キャラでサーバー枠を共有し、別サーバー/別アカウントとは分離。ゲーム内範囲は候補として表示する。
- 表示中のチェック/固定回数だけ完了率に含める。蓄積・資源を分母へ入れない。アビスは消費した分数、闘技場は報酬対象の勝利数と参加数を別々に入力する。

### 保存と互換性

新規キー `poketsuru-aion2-content-v1` に進捗と識別名/レベル/上限/時刻/曜日/自動計算設定/検索/区分/任意項目/非表示一覧を保存。Web Locksで1タブだけ保存可能とし、生データ比較で古いタブの上書きを拒否。自動保存は編集時だけ。読込失敗・容量不足・ロック不取得でもメモリ内変更とJSON書出しは使用できる。不正保存JSONは自動上書きせず、JSON復元の明示確認のみ置き換え可能。復元前の読込は1MiB/型/数値/日時/キー構造/既知タスクを検証し、未知の余分なフィールドを捨てる。古い非同期読込結果は変更/離脱時に無効化する。

既存自由入力の `poketsuru-aion2-checklist-v1` は保持。JSONも別形式。ZIP単体の `poketsuru:aion2-checklist:v1` は元来アカウント識別と安全な共有キーを持たないため自動移行しない。単体MVPのJSONは直接復元せずゲーム内残数を新管理へ入力する。

2. 日本サーバーの日次/週次リセット時刻と曜日、地域差、メンテ中の補充。

4. オードの回復基準時刻（個別タイマー/サーバー固定）、満タン・加入解除時の端数処理、サブスク上限840。

JSONは全キャラの本文と完了チェックを含むversion1形式。1 MiBまで、型/区分/boolean/ID一意性/文字数/件数を検査し、既知のフィールドのみ再構成する。復元候補の名前・件数・完了数と上書き範囲を表示し、確認チェックを入れて復元ボタンを押すまで現データと保存内容は変えない。候補の取消、復元操作の取消が可能。変更/新たな読込/離脱後の古い非同期完了は無視する。JSONに入力内容が含まれることを表示する。

検証は単体テスト、専用headless Edgeの明暗320/375/768/1280、キャラ切替・再読込・CRUD・手動リセット/取消・JSON書出し/検証/確認/復元・storage失敗・不正保存データ・入力エラー・キーボード・表示参照・送信なし。実機Safariとスクリーンリーダーの読み上げは未検証。
