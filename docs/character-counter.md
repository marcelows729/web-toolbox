# 文字数カウンターの数え方

既存の書記素（Intl.Segmenter、未対応時はUnicodeコードポイント）を維持。共有count.tsは変更せず、テキスト整形など他ツールの数え方も維持する。重複するコードポイント指標は追加しない。

既存「空白除外」はスペースだけでなくJSの空白・タブ・改行などを除いていたため、「空白・改行除外」へ名称と説明を明確化。改行だけを除きスペース・タブを残す指標がなかったので、「改行除外」を1項目追加。除去後の文字列を同じ書記素関数で数えるので、除去で隣接した結合文字が1文字になる場合も説明する。単語数は空白区切りで日本語の語の分割ではない。

入力欄ではCRLF・CRをLFへ統一。末尾の改行は行数を1増やし、空入力は全指標0。バイト数はこの入力のUTF-8符号化長。コピーは集計値ではなく入力本文。Clipboard APIへは入力文字列を渡すが、Windowsの実Edgeで読戻しがCRLFになることを確認したため、環境によるクリップボード側の改行変換を明記する。

上限がなかったため、貼付け・入力を50,000 UTF-16単位に制限。超過は集計前に拒否し、本文・集計を保持する。切り捨てない。空白だけの入力もコピーでき、編集・クリア・離脱後の古いコピー通知は既存hookで無効化。

通常npm testの`tests/character-counter.test.mjs`、通常npm run test:browserの`tests/character-counter-browser.mjs`で空入力、除外範囲、CRLF/LF、結合文字・家族emoji、UTF-8、上限、実コピー、ネイティブキーボード、コピー競合、入力の保存/通信/URL混入がないことを検証する。50,000文字の入力＋描画時間を実環境で測定するが、機器依存の固定速度を保証しない。31ツール、URL/ID、blue/navy、lazyloadを維持。新依存・設定・外部通信なし。
