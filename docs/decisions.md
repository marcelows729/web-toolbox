# Decisions

プロジェクトにおける主要な技術・設計判断を記録する。

## 2026-08-22 Frontend Framework

### Decision

React + TypeScriptを使用する。

### Reason

* Reactの利用経験を活かせる
* 小規模ツールをコンポーネント単位で追加しやすい
* 将来的にSpring BootとのFrontend / Backend分離が容易

## 2026-08-22 Build Tool

### Decision

Viteを使用する。

### Reason

* React + TypeScriptの開発環境を簡潔に構築できる
* 開発サーバーが高速
* 静的ファイルとしてビルド可能
* Cloudflare Pagesとの相性が良い

## 2026-08-22 Initial Hosting

### Decision

Cloudflare Pagesを使用する予定とする。

### Reason

* 静的サイトを低コストで公開できる
* GitHubとの連携が容易
* 将来的にSpring Bootを別Backendとして追加できる
* フロントエンドのホスティングとBackendを分離できる

## 2026-08-22 Backend

### Decision

初期バージョンではBackendを作成しない。

### Reason

初期ツールはブラウザ内で処理可能であり、Spring BootやDatabaseを追加するメリットがないため。

Backendが必要な機能を実装するタイミングでSpring Bootを追加する。

## 2026-08-22 Routing

### Decision

React Routerを使用する。

### Reason

* Reactで広く利用されているルーティングライブラリである
* `/tools/{tool-id}` 形式の個別URLを扱いやすい
* Version 0.1の規模に対して十分シンプルである
* 将来的にページ数やツール数が増えても対応しやすい

Version 0.1ではRoutingをTool Registryから自動生成せず、明示的に定義する。

自動生成は必要性が確認された段階で検討する。

## 2026-08-22 Branding

### Decision

サービス名を「ぽけつる」、ローマ字表記を「POKETSURU」とする。

### Brand Information

* ブランド名: ぽけつる
* ローマ字表記: POKETSURU
* キャッチコピー: ちょっと便利なツールを、ポケットに。
* ドメイン: https://poketsuru.com

### Reason

* 初期ツールを「持ち歩ける」感覚で使いやすくしたい

## 2026-08-22 Theme Support

### Decision

UI上は Light / Dark の2種類のみを扱う。

### Reason

* シンプルな切り替えUIにする
* 初回アクセス時にOSのテーマを考慮できる
* 手動選択後はLocalStorageを優先して状態を安定させる

### Implementation

* 初回アクセス時のみ OS の `prefers-color-scheme` を参照する
* OSがDarkの場合は初期Themeを `dark` とする
* それ以外は `light` とする
* ユーザーが手動で選択した場合、`poketsuru-theme` に保存する
* 以後は保存値を優先する
* テーマとロゴの判定は同じTheme状態を共有する

## 2026-09-08 ブラウザ内ツール5件の追加

### Decision

対象はIPv4 CIDR、SHA-256、進数変換、HTMLエスケープ・解除、割合・増減率の5件。標準APIと既存依存のみを使い、入力の外部送信・永続保存・バックエンドを追加しない。既存11件の登録・ルートを維持し、registryへのメタデータ追加とApp.tsxの明示的ルート追加で組み込む。

各ツールのUIと計算関数は同じツールディレクトリのTSXに配置する。5件で重複する出力、Copy、Clear、エラー、使い方、Privacy表示のみBrowserToolへ共通化する。既存ツールは移行しない。スタイルは既存CSSを再利用する。

### 計算仕様

| ツール | 決定事項 |
| --- | --- |
| IPv4 CIDR | IPv4の各オクテットは0〜255、プレフィックスは0〜32。前後の空白を除去し先頭ゼロは10進数。32bit符号付きビット演算を避け、Numberの正確な整数範囲内で計算する。/0〜/30は先頭・末尾をホストから除外。/31はポイントツーポイントとして2ホスト、/32は1ホスト。/0の総数は4294967296。予約アドレスの割り当て可否までは判定しない。 |
| SHA-256 | Web Crypto APIを使用。テキストはTextEncoderのUTF-8、空入力も有効。空白を保持しUnicode正規化・BOM追加はしない。textareaの改行はブラウザによるLF正規化を受ける。元のバイト列の検証にはファイル入力を使う。ファイルは空ファイルを含む生バイト列。両入力の上限は20 MiB、ファイルは読み込み前に容量確認。期待値は前後空白を除いた64桁16進数、大小文字を無視する。非対応環境では説明を表示し実行を無効化する。 |
| 進数変換 | BigIntを使用しNumber経由の精度損失を防ぐ。基数は2・8・10・16。数字部分4096桁以内。前後空白、先頭符号、先頭ゼロを許容。0b/0o/0xは基数一致時のみ許容。出力は接頭辞なし、小文字、符号付き絶対値表記。小数・指数・桁区切りを拒否する。16進数のeは数字として扱う。 |
| HTML | エスケープ対象は &、<、>、二重引用符、一重引用符。解除対象はamp/lt/gt/quot/aposの小文字名前付き参照と同じ5文字の10進・16進数値参照。セミコロン必須、その他は保持。置換は1回のみで再帰的解除をしない。結果はtextareaのvalueに設定し、HTML解析・挿入APIを使わない。 |
| 割合・増減率 | 部分÷全体×100、元の値×割合÷100、（変更後−変更前）÷変更前×100。負数・100%超を許容し分母ゼロを拒否。負の変更前は符号を保持した分母を使う。入力は数字100桁以内、小数部20桁以内の10進数。BigIntによる整数・倍率表現で計算し、結果のみ小数0〜10桁（初期2桁）で四捨五入する。半端がちょうど半分なら絶対値を増やす方向、負のゼロを抑制、末尾ゼロを保持。 |

### 非同期処理と操作

入力・設定変更、Clear、アンマウントで世代番号を更新する。古い計算やコピーの完了通知は破棄する。ファイル読み込みやdigest自体は中断できない。計算中は実行とCopyを無効化し、入力変更とClearは利用可能にする。Clearは入力・設定・出力・エラー・通知を初期化する。

Copyは空文字の有効な結果もコピーできる。Clipboard APIが使えない場合や権限拒否時はエラーを表示し、出力欄からの手動コピーを案内する。SHA-256の照合時を含め、Copyは出力全体を対象とする。

### Reason

新規ライブラリやバックエンドを増やさず、各ツールの境界値を明示する。割合計算には10進数の四捨五入を正確に行うためBigIntを使用する。入力変更後の古い非同期結果を表示しないことで、異なる入力のハッシュとの取り違えを防ぐ。

3. 一覧に既存11件と新規5件が表示されることを確認する。検索語「CIDR」「ハッシュ」「進数」「エスケープ」「増減率」と各英語キーワードで検索し、ネットワーク・開発・テキスト・一般のカテゴリを切り替える。HomePage本体は今回未提示のため、この反映は未検証。

6. SHA-256で空テキスト、空ファイル、abcの既知値、日本語、LF/CRLF、バイナリ、20 MiBちょうどと超過、期待値の一致・不一致・形式不正を確認する。ファイル選択解除と再選択も確認する。

## 2026-10-01 道具棚のデザイン刷新・お気に入り・最近使用

### Decision

既存16ツールの処理・URL・ブランドを維持し、アイボリー／深緑の面とブランドブルー、番号と用途マークを使う道具棚のデザインへ更新する。Header・一覧・共有入力面・結果・説明・フッターの文字、余白、境界、状態表現を揃える。ヒーローの道具チケットは既存ツールへのリンクで、新しいツールは追加しない。

お気に入りと最近使用は、`poketsuru-tool-shelf-v1` に `{ version: 1, favorites: string[], recent: string[] }` としてLocalStorage保存する。保存するのは既存ツールIDのみ。入力、結果、ファイル、日時は保存せず、外部送信・アカウント・新規依存は追加しない。

- お気に入りは新しく追加した順。再クリックで解除、再追加で先頭へ。カード上の星と詳細画面のボタンを利用する。
- 最近使用は既知のツールURLを開いた順。計算完了の記録ではない。重複は除去し、再訪で先頭へ、最大8件。履歴の一括消去はお気に入りに影響しない。
- 再読込で復元し、同一ブラウザの別タブでの保存変更・消去はstorageイベントで反映する。同時書込みは最後の保存を優先し、複数端末の同期はしない。
- 不正JSON、未知バージョン、65536文字超のデータは空状態で扱う。未知IDと重複を除去し、各リストの上限を適用する。初期読み取りだけでは保存内容を書き換えない。
- 読み取り／書き込み拒否や容量不足でも現在の画面内で操作を継続し、保存不可を表示する。ページ再読込後の復元は保証しない。
- 一覧は全ツール／お気に入り／最近使用を切り替え、検索とカテゴリは各リストの積集合で適用する。空状態には解除・一覧への導線を用意する。

### Accessibility and verification

カードリンクと星ボタンを独立させ、各ボタンに名前とaria-pressedを付ける。カテゴリと表示範囲はボタングループを使い、Tab・Enter・Space、skip link、focus-visibleを維持する。320pxからPC幅まで折り返し、選択中カテゴリは両テーマで青背景と白文字にする。hoverは短い浮き上がりを使い、prefers-reduced-motionでは動きとsmooth scrollを停止する。

Node標準テストで保存と復元、重複・順序・上限・解除・消去・保存失敗、静的リンク構造とカテゴリ文字コントラストを確認する。表示、実ブラウザの保存復元、キーボード、既存ツールの操作は実ブラウザで別途確認する。


## 2026-10-02 一般向けツール3件の追加

### Decision

- 単位変換、割り勘計算、ルーレット抽選を一般カテゴリへ追加。検索、お気に入り、最近使用は既存レジストリ経由で統合し、一覧の件数はレジストリから表示する。
- 入力・計算結果・抽選履歴はReactの画面内状態だけで保持する。入力を保存・送信する処理、外部API、新しい依存、バックエンドは追加しない。既存の道具棚にはツールIDだけを保存する。
- 単位は長さ（国際インチ・フィート・ヤード・マイルとSI）、重量（kg/g/mg/1000kgのトン）、体積（L/mL/m³/cm³）、面積（m²/cm²/km²/ha）、温度（℃/℉/K）。NIST SP 811 B.9と温度換算式を確認。畳、カップ、通貨など定義が変わる単位は含めない。
- 有限な十進数・指数表記・全角数字を受け付ける。温度以外は負数不可、温度は絶対零度以上。JavaScript数値で計算し、最大12桁の有効数字で表示する。入替は単位のみ交換し、結果は再計算する。
- 割り勘は0〜10億円と1〜100人の整数。正確な配分は最大1円差とし、10/100円単位の同額集金は切り上げて余りを明示する。人名、送金、税計算は扱わない。
- 抽選は2〜20件、1件Unicodeコードポイント50文字まで。前後空白・空行を除去しNFCで重複を検知する。crypto.getRandomValuesの32bit値をrejection samplingで均等な添字に変換し、結果を決めてから装飾回転する。候補編集・除外設定変更で履歴をリセットする。動きを減らす設定では結果を即時表示し、編集・画面離脱で古い抽選通知を破棄する。候補はReactのテキストとして描画する。

### References

- https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b9
- https://www.nist.gov/pml/owm/si-units-temperature

### Verification

自動テストは合計30件。ブラウザ操作・表示と配信の結果は実行ごとの報告で区別する。ホスティング側の解析設定はこの変更の対象外。


## 2026-10-02 遊びの診断2件を追加

### Decision

- 休日スタイル診断とポケット相棒診断だけを一般カテゴリへ追加。前者は今日の気分・ペースから過ごし方を提案し、後者は空想の旅からコンパス・えんぴつ・ランタン・しおりの相棒を提案する。結果の文章と独自SVGは用途ごとに分ける。
- 開始前と結果の両方に「遊びの診断です。性格や能力を判定するものではありません」と明示する。医学・心理学的判定、能力順位、精度表示はしない。氏名、誕生日、健康情報は聞かない。
- 各5問、各4択。選択肢は対応する結果へ1点を加え、最大点の結果を提案する。同点は表示した紹介順で決める。休日は余白・寄り道・手作業・分け合う日、相棒はコンパス・えんぴつ・ランタン・しおりの順。同じ回答には同じ結果を返し、選択した回答を理由として添える。得点は性格や能力の測定値ではない。
- 質問データと結果を各ツールに置き、2件で同じ進捗・戻る・回答修正・再開始・結果コピーのUIと集計だけを共有する。未回答は画面内エラーとし、質問切替時に見出しへフォーカスする。選択はネイティブradio、進捗と結果・コピー通知はaria-liveで知らせる。
- 回答と結果はReactのメモリ内だけで保持する。再開始・再読込・画面離脱で破棄し、保存・送信・URLへの埋め込みはしない。道具棚には既存仕様のツールIDだけを保存する。コピーは明示操作だけで行い、入力変更や再開始後に古い完了通知を反映しない。自動投稿、外部画像、新しい依存・API・追跡処理は追加しない。

### Verification

既存30テストに6件を追加し合計36件。両診断それぞれ全1024回答組合せを列挙し、全4結果の到達、合計5点、最大点と紹介順、決定性、回答由来の説明を確認する。固定した同点順によって結果の出現数は等しくない。これは娯楽の選び方であり、確率や統計的精度を示すものではない。


## 2026-10-02 ローカル画像ツール2件を追加

### Decision

- 画像サイズ変更・圧縮、画像を並べるだけを一般カテゴリに追加。既存の検索・道具棚・テーマを利用し、新しい依存・外部画像URL・サービス・追跡処理は追加しない。
- 入力は静止JPEG（一般的なSOF0/1/2）、PNG、WebP。ファイルの拡張子だけに頼らずシグネチャと構造・寸法を検査する。宣言MIMEが空または汎用バイナリのときは内容で判断し、別形式を示すMIMEなら拒否する。PNGはチャンク境界・CRC・IENDを確認しacTL/fcTL/fdATを拒否。WebPはRIFFサイズとVP8/VP8L/VP8Xを確認し、アニメーションフラグ・ANIM/ANMFを拒否する。JPEGのMPF、未対応符号化、デコード失敗も拒否する。完全な任意ファイルの安全性検証ではなく、構造検査とブラウザデコーダの両方を使う。
- 上限は1枚8 MiB、入力各辺8192 px・1200万画素。結合は2〜6枚、入力合計24 MiB・2000万画素。出力各辺8192 px・1200万画素・16 MiB。寸法と合計をデコード前・canvas作成前に検査する。上限内でも端末の資源によって処理失敗はあり得る。
- サイズ変更は指定した最大幅・高さに収まる比率固定の縮小を既定とし、拡大は明示選択する。JPEG/PNG/WebPへ出力し、JPEG/WebPの品質は10〜100。PNGでは品質を使わず、JPEGの透過は白背景。容量が増えた場合も増加量を表示する。
- 結合は横なら高さ、縦なら幅をそろえ、全画像を拡大しない範囲で指定上限以内に縮小する。画像の間に0〜200 pxの余白、白・黒・透過背景を選択しPNGで出力する。順序変更はボタンで行える。外周余白・自由配置・文字レイヤーは追加しない。
- createImageBitmapのfrom-imageでブラウザのEXIF向きを反映し、デコード後の寸法も検査する。canvas再書き出しで色・画質・メタデータが変わる場合があり、全メタデータ除去は保証しない。最低1 pxへの丸めで極端な縦横比に誤差が生じる場合を説明する。
- 読込みと書き出しは共有キューで順次処理し、各bitmapをfinallyでclose、canvasを解放する。プレビューは小さなPNGサムネイル。object URLは置換・消去・画面離脱時にrevokeする。ファイルの選び直し、設定変更、中断でrevisionを進め、古い処理が結果・通知を上書きしない。ネイティブ処理そのものの即時中止は保証しない。
- toBlobのnull・例外・20秒タイムアウト・16 MiB超過をエラーにする。要求MIMEと実際のBlob.typeが違う場合は拒否し、PNGフォールバックを別形式と誤表示しない。保存名は形式と一致した拡張子にし、制御文字などを整える。同名ファイルは表示番号で区別する。
- 画像・ファイル名・設定はメモリ内でのみ扱い、サーバー・解析・保存領域・URLへ渡さない。道具棚へ記録するのはツールIDだけ。利用者がダウンロード操作した画像だけを端末へ保存する。

## 2026-10-02: 単価比較とレシピ分量調整

買い物（2〜4商品）と料理（1〜20材料）の比例計算を追加。入力は画面内のメモリのみで保存・送信・URL埋め込みをしない。既存23ツールと棚IDを維持し、generalに2件追加して計25件。新しい依存・API・認証・配信設定は追加しない。
