# ページ情報・入力・内部リンクの点検

対象: 5be29efの公開27ツール。新規ツール・新依存・配信設定・計算や入力保存仕様の変更なし。

## 再現した問題と修正

1. 27ツールでdocument.titleとmeta descriptionがトップページの内容のままだった。Layoutで現在の登録名称・説明に更新し、一覧や未知URLへ移動した際にも対応する内容へ戻す。既存の紹介文を使い、宣伝文や新しい共有タグは増やさない。
2. 入力エラーはrole=alertで表示されていたが、22ツールで対象の入力や計算グループとの関係がなかった。エラーにIDを付け、該当入力からaria-describedbyで参照する。日付の2つの計算パネルは別IDを使い、年・月・日をグループ化する。入力を編集してエラーが消えると参照も消える。診断2件のfieldsetによる既存の関連付けは維持する。
3. 日付計算の開始日・終了日・基準日と、和暦変換の西暦日付のlabel forが、存在しないIDを参照していた。参照先を実際の年欄へ修正し、可視ラベルを日付グループの名前に使う。Timestampの日付グループも可視の日付ラベルと関連付ける。ラベルクリックによる年欄へのフォーカスと、Edgeのグループ名を確認する。
4. UUIDの件数欄はuuid-count-helpを参照していたが要素が存在しなかった。1〜100の整数という既存仕様の短い可視説明を追加し、参照を解決した。

元の可視ラベルは全27ツールに存在した。日付ピッカー用のopacity0・aria-hidden・tabIndex=-1の内部inputはユーザー向け入力欄と区別する。Text Diff・文字数・HTML変換で正常な入力から再現できない処理失敗を、新たな入力不正として扱わない。コピーや環境のエラーもあるため、すべての入力にaria-invalidを一律で付けることはしない。

## 問題がなかった項目

個別ページの見出し・可視説明は各ツールに合っていた。関連ツールの登録IDと実DOMリンクはすべて実在し、表示名も現在の登録名と一致した。戻るリンクは全27件で一覧へ戻った。この項目に修正は加えない。

- npm run lint / npm run build / git diff --check。変更したTSXのイベントハンドラも比較し、入力・計算・コピー・保存操作のハンドラは変更なし。
- 専用EdgeのCDP9222とpreview5173で node tests/page-clarity-browser.mjs。全27ページを一覧のリンクから開き、戻るリンクを実Enterで操作する。light/dark320pxで54回確認し、関連リンクも実際に開いてタイトル更新を確認する。
